# 🛡️ NexusShield

Most people don't get phished because they're careless. They get phished because nobody ever actually showed them what a fake login page or a spoofed sender address looks like. That's the gap NexusShield is trying to close — a mobile app that starts by figuring out where you're weak, then trains you on exactly that, and gives you a tool to actually check a suspicious link in the moment instead of guessing.

This was my final year project, built end-to-end: a React Native app, a FastAPI backend, and a CNN model I trained myself for phishing detection.

## What it actually does

You start with a 14-question cyber hygiene survey. It's not a quiz you can fail — it maps your answers to 9 categories (password habits, phishing awareness, network security, and so on) and figures out where you're already doing fine versus where you need the most help. That decides your starting difficulty level.

From there, training is flashcards and quizzes, 3 levels deep, 8 topics per level. These aren't pre-written — they're generated by an LLM the first time someone hits a topic, then cached in MongoDB so the 50th person to study "Phishing Awareness" isn't waiting on an API call.

The link checker is the part I spent the most time on. It's a CNN trained on URL structure — not a blocklist lookup — so it can catch a phishing domain that registered five minutes ago and has never been reported anywhere. The trade-off is a raw model like this tends to be overconfident, so I added temperature calibration and a URL-entropy check before anything gets flagged as outright phishing, rather than just trusting the raw sigmoid output.

There's also a live incident feed (real breach news and security articles pulled from RSS, not fake sample data), and a nudge system for push notifications that adapts — it uses Thompson Sampling to figure out per user which category of reminder is actually landing versus getting dismissed, instead of blasting the same generic tip on a fixed schedule.

## Stack

| Layer | Choice | Why |
|---|---|---|
| Mobile app | React Native (Expo) | Cross-platform, and Expo's build pipeline meant I didn't have to fight native Android/iOS tooling for a solo project |
| Backend | FastAPI | Async support and automatic docs made iterating on ~15 endpoints much less painful than Flask would've been |
| Database | MongoDB Atlas | Schema flexibility mattered more than relational integrity here — survey answers, cached content, and progress logs all look pretty different from each other |
| Phishing model | TensorFlow/Keras CNN | Trained on tokenized URL sequences, not a static blocklist |
| Content generation | Groq API (Llama 3.3) | Free tier, fast enough that flashcard generation doesn't feel like a loading screen |
| Auth | Firebase Admin SDK + Google OAuth | Push notifications were already going through Firebase, so auth came along for the ride |

## Running it

**Backend**
```bash
cd backend
python -m venv venv
venv\Scripts\activate          # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
```
Copy `.env.example` to `.env` and fill in your own MongoDB URI, Groq key, and Google OAuth credentials. Drop your own Firebase service-account file at `backend/firebase-key.json` — it's gitignored, so it won't accidentally get committed.
```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

**Frontend**
```bash
cd Frontend
npm install
```
Open `config.js` and set your machine's local network IP (from `ipconfig` / `ifconfig`) so your phone can actually reach the backend. Add your own `google-services.json` from the Firebase console.
```bash
npx expo start
```

## Known limitations / what I'd fix with more time

- Passwords in `auth.py` are stored as-is right now — `passlib` is already a dependency, hashing just hasn't been wired in yet.
- The backend URL is a local IP, so the app only works on the same network as the machine running the server. A real deployment (Render/Railway) would fix this.
- The phishing model runs in-process inside the FastAPI app — fine for a demo, not how I'd serve it at any real scale.

## A note on the phishing detection

This is built for awareness and education, not as a guaranteed security layer. It'll catch a lot, but "proceed with caution" means exactly that — use your own judgment on anything it doesn't confidently clear.
